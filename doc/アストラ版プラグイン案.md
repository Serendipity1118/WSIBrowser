# WSIBrowser スマホ向けプラグイン案

## 方針

スマートフォンならではの価値として、次の利用場面を重視する。

- 片手で操作する
- 外出先で使う
- 別のアプリや端末へ情報を渡す
- 入力や閲覧を途中で中断し、後から再開する
- 小さな画面で複数の情報を比較する

## 候補一覧

| プラグイン案 | 利用場面・主な機能 | 実現の見通し |
|---|---|---|
| 親指ナビ | ページ上部の検索、メニュー、次ページなどを画面下の操作パネルへ集約。左右の利き手にも対応 | 現行 SDK で着手可能。汎用の見出し・リンク移動から始め、サイト固有操作は別配布 |
| 入力途中レスキュー | 長文フォームの下書きを保存し、誤って戻った場合や再読み込み後に復元 | DOM 監視と storage で実現。初期版は利用者が指定した文章欄のみ保存 |
| 外出先比較ボード | 商品、宿、物件などの選択部分を URL とメモ付きで保存し、カード形式で比較 | storage とプラグインページで実現可能。初期版は手動選択で取り込む |
| 現地メモ付きブックマーク | 「入口は裏側」「この商品を確認」などのメモをページと一緒に保存し、再訪時に表示 | 現行 SDK で実現可能。位置情報による自動表示には追加対応が必要 |
| レシピ・手順ステップ表示 | 調理や作業の手順を1つずつ大きな文字で表示。大きな「次へ」ボタンと画面消灯防止を提供 | DOM 抽出、storage、wakeLock で実現。初期版は選択文章を手順へ分割 |
| 共有用カードメーカー | ページのタイトル、画像、選択文章、コメントを1枚の画像にまとめて共有 | 画像生成処理、files、share で実現。外部画像の取り込み方法は検証が必要 |
| 通信節約リーダー | 外出中は画像・動画を抑え、読みたい本文を端末に保存。必要な画像だけ後から表示 | blockResources、storage、プラグインページで実現。完全な Web ページ保存は別途設計が必要 |
| QR で受け渡し | 閲覧中の URL や選択テキストを QR コードで表示し、隣の人や別端末へ渡す | QR 生成ライブラリの同梱で実現可能。プラグイン内でのカメラ読み取りには追加ブリッジが必要 |
| 住所・日時アクション | 選択した住所を地図へ、日時とページ情報を予定へ、問い合わせ内容をメールへ渡す | OS の共有機能から着手可能。カレンダーへの直接登録などは追加対応が必要 |

## 1. 親指ナビ

スマートフォンでは、ページ上部にある検索欄やメニューへ指が届きにくい。よく使う操作を画面下へ集約し、片手操作を助ける。

初期版の機能:

- ページ先頭・末尾へ移動
- 前・次の見出しへ移動
- ページ内検索欄へフォーカス
- 前・次ページらしいリンクを候補表示
- パネルを画面の左寄り・右寄りへ切り替え
- サイトごとの表示位置と機能設定を保存

利用する主な API:

- `WSI.addButton`
- `WSI.addPanel`
- `WSI.settings`
- `WSI.onPageLoad`

最初は HTML の見出しやリンクを使った汎用操作を提供する。特定サイトの DOM セレクタに依存する操作は非公開のサイト固有プラグインへ分ける。

## 2. 入力途中レスキュー

スマートフォンで時間をかけて入力した文章が、誤操作、再読み込み、アプリの中断などで消える問題を防ぐ。

初期版の機能:

- 利用者が選んだ `textarea` または文章入力欄を監視
- 入力内容を一定間隔で自動保存
- URL と入力欄の特徴を組み合わせて下書きを識別
- 再訪時に復元候補を表示
- 現在の内容を上書きする前にプレビュー
- 送信後または利用者操作で下書きを削除
- 保存済みであることを小さく表示

利用する主な API:

- `WSI.storage`
- `WSI.toast`
- `WSI.dialog`
- `WSI.onPageLoad`

パスワード欄、カード番号、ワンタイムコードなどは保存対象から除外する。初期版では自動検出した全フォームを保存せず、利用者が明示的に指定した文章欄だけを対象にする。

## 3. 外出先比較ボード

商品、宿、物件、店舗、記事などを小さな画面で比較するとき、複数タブを何度も往復せずに済むようにする。

初期版の機能:

- 選択テキスト、ページタイトル、URLをカードとして保存
- カードにメモと評価を追加
- 比較したい項目を利用者が追加
- カードを横並びまたは一覧で表示
- 不要な候補を非表示にして絞り込み
- 比較結果を Markdown またはテキストで共有

利用する主な API:

- `WSI.addButton`
- `WSI.storage`
- `WSI.ui.openPage`
- `WSI.files.save`
- `WSI.share`

汎用版では利用者が選択した情報を取り込む。価格や住所などをサイトから自動抽出する場合は、サイト固有版として管理する。

## 4. 現地メモ付きブックマーク

外出先でページを見直したときに、その場所や用件に関する短いメモを表示する。

想定例:

- 店舗ページに「入口は建物の裏側」と保存
- 商品ページに「店頭でサイズを確認」と保存
- 施設ページに「受付で予約名を伝える」と保存
- 記事ページに「帰宅後に続きを読む」と保存

利用する主な API:

- `WSI.storage`
- `WSI.addButton`
- `WSI.toast`
- `WSI.onPageLoad`

URL のクエリ文字列を除外するなど、同じページと判断する規則を設定できるようにする。位置情報を使った自動表示は、将来の位置情報ブリッジ追加後の機能とする。

## 5. レシピ・手順ステップ表示

料理、組み立て、整備、運動などの作業中に、Web ページの手順を1つずつ大きく表示する。

初期版の機能:

- 選択文章またはリスト要素を手順として取り込む
- 1画面に1手順を大きく表示
- 画面下部に大きな「前へ」「次へ」ボタンを配置
- 現在の手順番号を保存
- 作業中の画面消灯を防止
- 原文ページへすぐ戻れるリンクを表示

利用する主な API:

- `WSI.ui.openPage`
- `WSI.storage`
- `WSI.wakeLock`
- `WSI.settings`

自動的な本文解析だけに頼らず、利用者が対象範囲を選べるようにすると、多様なページで安定して使える。

## 6. 共有用カードメーカー

Web ページの情報を、メッセージアプリや SNS へ渡しやすい1枚のカード画像にする。

初期版の機能:

- タイトル、URL、選択文章をカードへ配置
- ページ画像または利用者が選んだ画像を追加
- 短いコメントを追加
- 縦長・正方形のレイアウトを選択
- 画像ファイルとして保存または共有

利用する主な API:

- `WSI.files.save`
- `WSI.share`
- `WSI.settings`
- `WSI.ui.openPage`

外部画像は CORS や認証の影響を受けるため、`WSI.fetch` で取得できる画像、ページ内で描画できる画像、利用者が選択した画像の順に対応範囲を検討する。

## 7. 通信節約リーダー

移動中や通信量を抑えたい場面で、本文を優先して閲覧できるようにする。

初期版の機能:

- 画像・動画リソースを抑制
- 本文中心の簡易表示
- 必要な画像だけタップして読み込む
- 抽出した本文をプラグイン内に保存
- 保存済みの記事をプラグインページで読む
- 通信節約モードをホストごとに切り替え

利用する主な API:

- `WSI.blockResources`
- `WSI.storage`
- `WSI.ui.openPage`
- `WSI.menu`

初期版は本文とメタデータの保存を対象とする。元ページを完全に再現するオフライン保存には、ファイル構成や容量制限を含む追加設計が必要になる。

## 8. QR で受け渡し

クリップボードやアカウントを共有していない端末へ、閲覧中の情報をその場で渡す。

初期版の機能:

- 現在の URL を QR コードとして表示
- 選択テキストを QR コードとして表示
- 長いデータを扱えない場合は URL のみに切り替え
- 明るさと余白を調整し、読み取りやすく表示
- QR コード画像を保存・共有

利用する主な API:

- `WSI.ui.openPage`
- `WSI.files.save`
- `WSI.share`

QR コードの生成は JavaScript ライブラリをプラグインへ同梱すれば実現できる。カメラを使った読み取りをプラグイン内で提供するには、専用ブリッジの追加が必要になる。

## 9. 住所・日時アクション

ページ内の住所、日時、電話番号、メールアドレスを選択し、スマートフォンの別アプリへ渡す。

初期版の機能:

- 選択した住所を地図アプリ向けの共有内容に整形
- 日時、タイトル、URLを予定登録向けの文章に整形
- 電話番号やメールアドレスを抽出
- 問い合わせ内容をメール向けに整形
- 元ページのタイトルと URL を自動付加

利用する主な API:

- `WSI.share`
- `WSI.clipboard.write`
- `WSI.addPanel`

OS の共有シートを使う初期版は現行 SDK で実現できる。カレンダーや地図アプリを直接指定して開く機能は、専用のネイティブブリッジを追加する場合に検討する。

## 優先候補

### 1. 親指ナビ

スマートフォン特有の「画面上部に指が届かない」という問題を直接解決する。見出し移動、検索欄への移動、先頭・末尾への移動だけでも効果を確認しやすい。

### 2. 入力途中レスキュー

スマートフォンで苦労して入力した文章が消える問題を防げる。「保存済み」の表示と、再訪時の復元プレビューまで含めると、安心して使える機能になる。

### 3. 外出先比較ボード

小さな画面でのタブ往復を減らせる。「選択範囲を保存、メモ追加、比較一覧、共有」という流れなら、買い物だけでなく旅行、物件探し、記事調査にも使える。

## 推奨する開発順

1. 親指ナビ
2. 入力途中レスキュー
3. 外出先比較ボード
4. レシピ・手順ステップ表示
5. 通信節約リーダー
6. QR で受け渡し

最初の3案は現行 SDK の機能で主要部分を作ることができ、スマートフォンで WSIBrowser を使う理由も伝わりやすい。後半では `wakeLock`、`blockResources`、`files`、`share` などのネイティブ連携を段階的に活用する。

## 共通の注意点

- タップ対象は44px以上を基本とし、セーフエリアを考慮する。
- 操作ボタンは画面下部へ配置し、左右の利き手に対応する。
- アプリが中断されても再開できるよう、進捗や下書きを `WSI.storage` に保存する。
- iOS のバックグラウンド実行を前提にせず、アプリ復帰時に処理を再開する。
- パスワード、カード番号、ワンタイムコードなどを通常の storage に保存しない。
- 共有前、復元前、外部アプリへ渡す前に内容を確認できるようにする。
- 汎用プラグインだけを公開リポジトリへ置き、サイト固有の URL や DOM セレクタは非公開リポジトリで管理する。
