# WSIBrowser プラグイン案

## 方針

WSIBrowser は、通常の DOM 操作に加えて、設定画面、バックグラウンドワーカー、複数タブ巡回、ファイル保存、共有、PiP、リソースブロックなどをプラグインから利用できる。

以下では、本体機能と重複せず、WSIBrowser の強みを活かせるプラグインを優先して挙げる。

## 候補一覧

| 優先度 | プラグイン案 | 主な機能 | 実装規模 |
|---|---|---|---|
| 1 | Web ツールボックス | 広告・固定ヘッダー非表示、ダークモード、文字サイズ、画像 OFF、ページ内検索補助 | 小〜中 |
| 2 | Web クリッパー | 本文を Markdown で保存・共有し、タイトル、URL、日時、選択範囲を付加 | 小 |
| 3 | ページ更新チェッカー | 指定ページの本文や価格の変化を検出し、差分履歴を表示 | 中 |
| 4 | フォーム入力テンプレート | 住所や定型文をプロファイル別に保存し、フォームへ一括入力 | 中 |
| 5 | テーブル・一覧エクスポーター | HTML テーブルや繰り返し要素を CSV・JSON として保存 | 中 |
| 6 | 読書モード・読み上げ補助 | 本文抽出、不要要素の除去、読書進捗保存、長文分割コピー | 中 |
| 7 | リンク収集・一括確認 | ページ内リンクを抽出し、重複、外部リンク、リンク切れを一覧化 | 中 |
| 8 | セッション切替 | Cookie、サイトデータ、資格情報プロファイルを使ったアカウント切替 | 中〜大 |
| 9 | 動画集中モード | 動画以外を隠す、画面消灯防止、PiP、再生位置保存 | 小〜中 |
| 10 | Web QA アシスタント | 見出し構造、alt、フォームラベル、リンク、viewport などを検査 | 中 |

## 1. Web ツールボックス

全サイトで使える、日常的な閲覧改善機能をまとめたプラグイン。

最初のバージョンでは次の機能に限定する。

- 文字サイズ、行間、コンテンツ幅の調整
- CSS による簡易ダークモード
- タップして選んだ要素の非表示
- 画像・動画の読み込み抑制
- ホストごとの設定保存

利用する主な API:

- `WSI.addButton` / `WSI.addPanel`: 操作 UI
- `WSI.settings`: サイト別の表示設定
- `WSI.settings.onChange`: 設定の即時反映
- `WSI.blockResources`: 画像・動画の通信抑制
- `WSI.menu`: 常設メニュー

対象を全サイトにでき、インストール直後から効果が分かりやすいため、最優先候補とする。

## 2. Web クリッパー

現在の `markdown-copy` サンプルを実用品へ発展させる。

- ページ本文または選択範囲を抽出
- Markdown / プレーンテキスト / HTML の出力切替
- タイトル、URL、保存日時の付加
- ページ内画像 URL の一覧化
- ファイル保存と共有シートへの送信
- サイト別の不要要素ルール

利用する主な API:

- `WSI.addButton` / `WSI.addPanel`
- `WSI.settings`
- `WSI.files.save`
- `WSI.share`
- `WSI.clipboard.write`

既存サンプルを土台にできるため、小さな実装で公開可能な実用品にしやすい。

## 3. ページ更新チェッカー

利用者が指定したページ領域を保存し、次回確認時に内容の変化を検出する。

- ページ全体または選択した要素のスナップショット保存
- 前回との差分表示
- 価格や在庫文言など、特定テキストの抽出
- アプリ起動時・復帰時・手動操作時の再確認
- 変更履歴をプラグインページで表示

利用する主な API:

- `WSI.storage`
- `WSI.tabs`
- `WSI.runtime.onSuspend` / `WSI.runtime.onResume`
- `WSI.ui.openPage`
- `WSI.toast`

iOS ではバックグラウンド処理を継続できないため、常時監視ではなく、アプリ起動時、復帰時、利用者操作時に確認する設計とする。

## 4. フォーム入力テンプレート

頻繁に入力する住所、連絡先、定型文などを保存し、フォームへまとめて入力する。

- 複数プロファイルの保存
- 入力項目とテンプレート項目の対応付け
- プレビュー後の一括入力
- パスワードなどの機密項目は資格情報ストアに分離
- サイトごとの入力ルール保存

利用する主な API:

- `WSI.settings`
- `WSI.storage`
- `WSI.credentials`
- `WSI.dialog`

誤送信を避けるため、入力までを自動化し、フォーム送信は原則として利用者操作に残す。

## 5. テーブル・一覧エクスポーター

ページ内の表や繰り返し表示されるカードを認識し、構造化データとして出力する。

- HTML テーブルの自動検出
- 利用者が指定した繰り返し要素から列を抽出
- 複数ページの巡回と結合
- CSV / JSON 出力
- 文字コード、区切り文字、列名の設定

利用する主な API:

- `WSI.addPanel`
- `WSI.tabs`
- `WSI.storage`
- `WSI.files.save`
- `WSI.share`

汎用版では利用者自身が抽出対象を指定する。サイト固有セレクタを含む版は非公開リポジトリで管理する。

## 6. 読書モード・読み上げ補助

記事や長文ページを読みやすい表示へ変換する。

- 本文、見出し、画像の抽出
- ナビゲーションや広告などの除去
- 文字サイズ、行間、テーマ変更
- スクロール位置と読書進捗の保存
- 読み上げアプリへ渡しやすい長文分割・共有

独自の音声合成ブリッジを追加しなくても、初期版は整形テキストを OS の共有機能へ渡す形で実現できる。

## 7. リンク収集・一括確認

ページに含まれるリンクを収集し、調査やサイト保守を支援する。

- 内部リンクと外部リンクの分類
- 重複、アンカー、mailto、tel の分類
- リダイレクト先と HTTP ステータスの確認
- リンク切れ候補の表示
- CSV 出力

大量アクセスを避けるため、確認間隔や同時実行数は `WSI.policy` から制御できる構成が望ましい。

## 8. セッション切替

同じサービスの複数アカウントを切り替えやすくする。

- 資格情報のプロファイル管理
- 対象ドメインの Cookie・サイトデータ消去
- ログインページへの移動
- 必要に応じたフォーム入力補助

利用する主な API:

- `WSI.credentials`
- `WSI.siteData.clear`
- `WSI.ui.openUrl`
- `WSI.settings`

資格情報を扱うため、権限要求と利用者への説明を明確にし、ログへ値を出さない。

## 9. 動画集中モード

動画ページを小さな画面でも扱いやすくする。

- 動画以外のページ要素を非表示
- 画面消灯防止
- Android の PiP 起動
- 再生位置の保存と復元
- 動画読み込みを妨げる不要リソースの抑制

利用する主な API:

- `WSI.wakeLock`
- `WSI.pip`
- `WSI.storage`
- `WSI.blockResources`

PiP は Android 中心の機能とし、iOS では非対応であることを UI 上で明示する。

## 10. Web QA アシスタント

Web ページの品質を端末上で簡易検査する、開発者・運用担当者向けプラグイン。

- 見出しレベルの飛びや重複を検出
- 画像の `alt`、フォームの `label` を確認
- 空リンク、重複 ID、横スクロールを検出
- title、description、canonical、viewport を表示
- 結果を JSON / Markdown で保存・共有

外部サービスなしでも基本検査を完結でき、WSIBrowser 自体のプラグイン開発確認にも利用できる。

## サイト固有プラグインへの展開

事業用途では、汎用プラグインを基礎に次のようなサイト固有版へ展開できる。

- 管理画面の一覧を CSV 化
- 複数ページを巡回して集計
- 定型作業の入力・クリック支援
- データ欠損や状態異常の検査
- 複数アカウントの切り替え
- 日報・報告文の生成

公開リポジトリには汎用プラグイン、雛形、デモだけを置く。特定サイトの URL、DOM セレクタ、業務知識、認証情報を含むプラグインは非公開リポジトリで管理する。

## 推奨する開発順

1. Web クリッパー
2. Web ツールボックス
3. テーブル・一覧エクスポーター
4. ページ更新チェッカー
5. フォーム入力テンプレート

Web クリッパーは既存サンプルを利用して短期間で完成させやすい。次に全サイトで価値を出せる Web ツールボックスを作り、その後にワーカーや複数タブを使う高度なプラグインへ進む。

## 共通の設計上の注意

- DOM 要素が存在しない場合はエラーにせず no-op とする。
- SPA 遷移後も `WSI.onPageLoad` で再適用する。
- サイト固有のセレクタは機能本体から分離する。
- 大量アクセスを行う処理には間隔、上限、中断・再開を設ける。
- ワーカーの進捗は `WSI.storage` に保存し、アプリ復帰時に継続できるようにする。
- 機密情報は `WSI.credentials` に保存し、通常の storage やログへ出さない。
- ファイル、資格情報、タブ操作などの強い権限は必要最小限にする。
- 自動操作では最終的な送信、購入、削除などの不可逆操作を利用者に確認させる。
