# 実装プラン: WSI Browser (Flutter) ホスト・SDK・バックエンド

本書は [要件定義.md](要件定義.md) を Flutter で実装するための作業計画である。フェーズごとにタスクを分割し、成果物と完了条件を定める。サイト固有プラグインの移植計画は各プラグインのリポジトリ側に置き、本書ではそのフェーズ番号 (P6 〜 P8) を予約するにとどめる。

---

## 1. 方針

### 1.1 決定事項 (2026-09-09 確認済み)

| 項目 | 決定 | 理由 |
|---|---|---|
| アプリ | 新しい ID `jp.serendipy.wsibrowser`、アプリ名 WSI Browser の汎用ブラウザ | 特定サイトに依存しない製品として配布する |
| ホストの作り方 | WSIBrowser リポジトリ (旧 MobilePlugin、公開) に新規の Flutter プロジェクトとして作る | 既存の WebView ラッパーアプリを土台にせず、資産 (ネイティブコード、計画書の実測事項) だけを移す |
| WebView | flutter_inappwebview 6 系 | UserScript、`callHandler`、HeadlessInAppWebView、独自スキームが揃う唯一のパッケージ |
| SDK コア | `packages/wsi_sdk` に抽出し、Chrome 版と Flutter 版のアダプタを生成する。Chrome 版 WSI も新 SDK に載せ替える | 同じプラグインが両方で動くことを契約テストで保証し、将来の乖離を防ぐ |
| サイト固有プラグイン | アプリに同梱しない。非公開リポジトリで開発し、Cloudflare (R2 / Pages) で ZIP を配布する。ホストは `updateUrl` で新版を検知して利用者に確認する | 公開リポジトリにサイト固有の自動操作を置かない。ストア審査でサイト固有機能が見えず、プラグイン更新に審査が不要 |
| 改変対策 | 署名は行わない。制限値はサーバー (Workers + D1) からポリシー値として配信し、プラグインが従う | 値の変更を即時反映できる。クライアント改変の完全防止は目的にしない |
| プラン (課金) | 当面なし | プラン体系は別書で設計する |
| データベース | Firebase は使わない。Cloudflare Workers + D1 を `apps/api` に置く | 既存アプリのバックエンドに依存しない |
| iOS 背面移行時のワーカー | 一時停止し、復帰時に続きから再開する | iOS の制約を受け入れ、状態を storage に残して安定させる |
| プラグインの単位 | サイトごとに 1 プラグイン。機能は `src/features/` に 1 機能 1 ファイルで置き、esbuild で `main.js` に束ねる | 機能追加は features に 1 ファイル足すだけで済む |

### 1.2 前提事項 (2026-09-09 確認済み)

以下は当初「未確認」としていたが、利用者に確認し確定した。

| 項目 | 前提 | 変更する場合の影響 |
|---|---|---|
| 対応 OS | iOS 15 以上、Android 8 (API 26) 以上 | flutter_inappwebview の下限に合わせている。下げると一部 API が使えない |
| プラグインページの実装 | Vanilla HTML / CSS / JS (WSI と同じ方針) | フレームワークを入れると ZIP が大きくなり、CSP と CDN 不可の制約に当たる |
| プラグインのビルド | esbuild で `src/main.js` と `src/worker.js` を束ねる | 素の結合でも可だが、features の import 解決が手作業になる |
| ホストのスタートページ | プラグイン一覧と URL 入力の簡易ページ | 利用者は初期 URL を設定で変えられる |
| API 認証 | 当面なし。書き込みは feedback のみでレート制限 | プラン導入時に追加する |
| WSI リポジトリへの変更 (P0-04) | WSI 側は feature ブランチで作業し、既存 e2e が通った時点でコミットする。main へのマージとストア公開は利用者が判断する | main 直接コミットにすると Chrome 版の公開タイミングを制御しにくい |
| コミット粒度 | WSIBrowser、pokeparaPlugin ともフェーズ単位で 1 コミット。push はしない | タスク単位にすると履歴は細かくなるが、フェーズ途中の中間状態がコミットに残る |
| Cloudflare アカウント | 既存アカウント (develop@serendipy.jp) に `wsi-api` (Worker、D1)、`wsi-plugins` (R2) を作成済み (2026-09-10)。pokeplus のリソースには触れない | 別アカウントにすると wrangler のログイン切替が必要 |
| 公開 URL | 当面 workers.dev (`wsi-api.pokeplus-dev.workers.dev`)。カスタムドメインは P9 前に検討 | URL はプラグインの `plugin.json` とホスト設定で差し替えられる設計にする |
| ZIP と配布ページ | R2 は非公開のまま、Worker が `GET /v1/plugins/:id/releases/:version.zip` で返す。配布ページも Worker の静的アセット | r2.dev 公開はレート制限があり、Pages を足すと URL が 2 系統になる |
| iOS ビルド | Windows のためローカル不可。Codemagic (アプリ WSIBrowser 追加済み) + TestFlight で実機検証。Bundle ID と App Store Connect の App は登録済み | Google Play Console は P9 で登録 |

### 2.1 プラグイン追加の手順 (完成後の運用)

1. `wsi-plugin create <id>` で雛形から生成する (公開なら `plugins/<id>/`、非公開なら別リポジトリ)
2. `plugin.json` の `domains` と `permissions` を書く
3. `src/features/` に機能ファイルを足し、`src/main.js` の振り分け表に 1 行加える
4. `wsi-plugin dev-serve` で PC から配信し、開発者モードの WSI Browser で受け取る
5. `wsi-plugin pack` で ZIP 化し、`wsi-plugin publish` で R2 へ置き、`plugin_releases` に登録する。利用者のホストが `updateUrl` で検知する

ホスト側の変更は不要である。ホストの変更が要るのは、新しいネイティブ機能 (`bridge_ops/` に 1 ファイル追加と `registry.dart` への追記) を足すときだけとする。

### 2.2 プラグインの内部規約 (雛形が強制する形)

- `src/main.js` は `location.pathname` を見て features の `matches` と照合し、一致した feature の `run(WSI, ctx)` を呼ぶだけにする
- feature は `{ id, matches: [glob], runAt, run(WSI, ctx) }` を export する。DOM id は `<pluginId>-<feature>-*` で名前空間を分ける
- サイトのセレクタは `src/lib/selectors.js` に集約し、マークアップ変更時の修正点を 1 箇所にする
- `worker.js` は状態機械 (idle / running / paused) を持ち、ページ側とは `WSI.runtime` でやり取りする。`onSuspend` で状態を保存し `onResume` で再開する
- 制限値は `src/lib/policy.js` が `WSI.policy.get` で読む。コード内に定数として持たない

## 6. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| 公開リポジトリへのサイト固有情報の混入 | 絶対条件違反 | サイト固有プラグインは非公開リポジトリのみ。P0-09 の検査と P10-04 の規約 |
| iOS で既存 WebView への `loadRequest` が無視される (実機で確認済みの既知不具合) | tabs API と巡回が止まる | P4-07 で iOS は毎回生成する方針を固定し、メモリ増加を長時間計測する |
| `https` から `http` へのリダイレクトが遮断される | 新ドメインでページが開けない | P1-06 で `https` 読み直しをホストに実装し、新プラグイン追加時のチェック項目にする |
| 非表示 WebView では見た目の検証ができない | 自動処理中の DOM 操作の失敗に気づけない | 注入結果の自己診断 (位置、可視性) を `WSI.log` に出し、`run` の戻り値で確認する |
| iOS の背面移行でワーカーが止まる | 自動処理が途中で止まる | suspend / resume を仕様化 (決定事項) し、状態を storage に残す。wakeLock で画面を保つ運用を設定画面で案内する |
| Android WebView にメインワールドしかない | プラグイン間、ページとの変数衝突 | `WSI` をグローバルに置かない。DOM id を `<pluginId>-<feature>-*` で分ける |
| サイト側のマークアップ変更 | プラグインが黙って壊れる | セレクタを `selectors.js` に集約し、feature は対象要素がなければ no-op。プラグイン差し替えで対応でき、アプリ更新は不要 |
| ストア審査 (Apple 2.5.2) | リジェクト | 汎用ブラウザとして申請し、利用者インポートと手動更新を審査ノートに明記。自動配信機能を持たない |
| ポリシー値のクライアント改変 | 制限値の迂回 | 決定事項として完全防止は目的外。サーバーで値を変えられることと、`policy.defaults` へのフォールバックで最低限を担保する |
| flutter_inappwebview のバージョン差 | API 変更でビルドが壊れる | 6 系に固定し、pubspec で理由をコメントする |
