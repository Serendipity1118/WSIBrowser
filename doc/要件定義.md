# 要件定義書: WSI Browser (Web System Injection for Mobile)

## プロジェクト概要

**プロジェクト名:** WSI Mobile
**アプリ名:** WSI Browser
**バンドル ID:** `jp.serendipy.wsibrowser`
**バージョン:** v1.2 (本書)
**作成日:** 2026-09-09
**形態:** Flutter アプリ (iOS / Android)。flutter_inappwebview をエンジンとする自前ブラウザ。バックエンドは Cloudflare Workers + D1
**参照プロジェクト:**
- [WebSystemInjection](https://github.com/Serendipity1118/WebSystemInjection) v1.3.0 (Chrome 拡張版 WSI)。プラグイン形式と SDK の原点。本計画で SDK コアを共通化し、Chrome 版も新 SDK に載せ替える

サイト固有のプラグイン (最初の本格プラグイン) の要件は、非公開リポジトリ側の要件定義に分離している。本書はホスト、SDK、プラグイン形式、バックエンドの汎用要件のみを扱う。

### 背景

Chrome 拡張版 WSI は「ZIP プラグインをインポートし、宣言したドメインでだけ実行する」開発者向けプラットフォームとして機能している。しかしスマートフォンの Chrome は拡張機能に対応しておらず、同じ仕組みを使えない。

一方、特定サイトを WebView で包み、URL を照合して JavaScript を注入し、JavaScriptChannel でネイティブへ戻す形の Flutter アプリは、WSI の「ドメイン照合、注入、ブリッジ」と同型の構造を持つ。ただし機能がアプリ本体に集中し、新しいサイトやサイト側のマークアップ変更のたびにアプリ更新とストア審査が必要になる。

### 目的

1. WSI と同じプラグイン形式と SDK を、iOS と Android の両方で動かす
2. サイト固有の機能を「汎用ホスト (WSI Browser) + 別配布のプラグイン」に分解できるようにする
3. 以後のサイト対応や機能追加を、アプリ更新とストア審査なしで行えるようにする

### 絶対条件

- ホストはサイト固有の知識 (セレクタ、自動操作、プロンプト、URL) を持たない。それらはすべてプラグイン側に置く
- ホストとバックエンドは、既存アプリのバックエンド (Firebase 等) に依存せず、アクセスもしない。バックエンドは Cloudflare Workers + D1 で新規に用意する
- 本リポジトリは公開のため、サイト固有プラグインのソースと固有情報を含めない

### 位置づけ

```
WSI (Chrome拡張) ──共通 SDK コア (packages/wsi_sdk)── WSI Browser (Flutter, 汎用ホスト)
                                                          │ ZIP インポート
                                          ┌───────────────┼───────────────┐
                                   サイト固有プラグイン   汎用サンプル    将来の他サイト
                                   (非公開リポジトリ・    (WSI 同梱 7 個)  プラグイン
                                    Cloudflare で別配布)
                                          │
                                   apps/api (Workers + D1): ポリシー値配信、更新情報、フィードバック
```

### 決定事項 (2026-09-09 確認済み)

| 項目 | 決定 |

| サイト固有プラグイン | アプリに同梱しない。Cloudflare で ZIP を配布し、利用者がインポートする。ホストは更新を検知して利用者に確認する |

## 用語

| 用語 | 意味 |
|---|---|
| ホスト | WSI Browser アプリ本体。プラグインを読み込み、実行し、ネイティブ機能を提供する。特定サイトの知識を持たない |
| プラグイン | `plugin.json` と JS / CSS / HTML を ZIP にまとめた機能単位 |
| SDK | プラグインから見える `WSI` オブジェクト。Chrome 版と共通の SDK コアと、ホスト固有のアダプタで構成する |
| ブリッジ | ページ内 JS とホスト (Dart) の間の通信路。`callHandler('wsi', ...)` の 1 本に統一する |
| サイトタブ | ユーザーが閲覧する通常の WebView |
| プラグインページ | プラグイン同梱の HTML をホストが表示する専用 WebView。設定画面などに使う |
| ワーカー | プラグインの常駐スクリプト。非表示 WebView で動き、ページ遷移で消えない |
| ポリシー | サーバーから配信される、プラグインが従うべき値 (最小間隔など)。`WSI.policy` で取得する |
| API | `apps/api` の Cloudflare Workers。D1 を読み書きする |
| メインワールド | ページ自身の JS と同じグローバル空間。Android WebView はこれしか持たない |

## アーキテクチャ

```
┌─ WSI Browser (Flutter) ─────────────────────────────────────────────┐
│ UI 層      : タブ / URL バー / プラグイン管理 / メニュー / ログ画面     │
│ Runtime 層 : PluginRepository (drift) / Validator / DomainMatcher      │
│              Injector / Bridge / WorkerManager / TabManager / MenuBus │
│              UpdateChecker / PolicyCache                              │
│ Native 層  : credentials / device / share / files / clipboard          │
│              wakeLock / pip / blockResources / cookies                 │
│ WebView 群 (flutter_inappwebview)                                     │
│   [サイトタブ]×N   [プラグインページ]×N   [ヘッドレスワーカー]×N        │
└───────────────────────────────────────────────────────────────────────┘
            ▲ window.flutter_inappwebview.callHandler('wsi', {token, op, ...})
   wsi-sdk-core.js (UserScript) → __wsiRun(pluginId, token, config, code)
                                → new Function('WSI', code)(WSI)

┌─ apps/api (Cloudflare Workers + D1) ─────────────────────────────────┐
│ GET  /v1/plugins/:id/policy     ポリシー値                             │
│ GET  /v1/plugins/:id/latest     最新バージョンと ZIP の URL             │
│ POST /v1/feedback               フィードバック                         │
│ (静的) R2 非公開 + Worker 配信   プラグイン ZIP と配布ページ             │
└───────────────────────────────────────────────────────────────────────┘
```

### 実行の流れ

1. ホストは各サイトタブに SDK コアを `UserScript` (AT_DOCUMENT_START) として登録する
2. `onLoadStart` / `onLoadStop` でホスト名を取り、有効かつドメインが一致するプラグインを抽出する
3. プラグインごとに使い捨てトークンを発行し、CSS を注入したのち `__wsiRun` を評価する
4. プラグインは `WSI` を通じて特権操作を要求し、ブリッジはトークンから pluginId と許可権限を引いて処理する
5. `background` を宣言したプラグインは、アプリ起動時にワーカーとして非表示 WebView で起動される
6. `pages` と `menu` を宣言したプラグインは、ホストのメニューから自分の HTML 画面を開ける
7. `policy.url` を宣言したプラグインは、ホストがポリシー値を取得してキャッシュし、`WSI.policy.get` で返す
8. `updateUrl` を宣言したプラグインは、ホストが起動時と 1 日 1 回に最新版を確認し、利用者へ更新を提案する

### Chrome 版 WSI との対応

| Chrome 拡張版 | WSI Browser |
|---|---|
| `tabs.onUpdated` | `onLoadStop` / `onUpdateVisitedHistory` |
| `scripting.executeScript` (MAIN) | `UserScript` + `evaluateJavascript` |
| `scripting.insertCSS` | `injectCSSCode` |
| `chrome.storage.local` | drift (SQLite) |
| Service Worker 経由の fetch | dio |
| `postMessage` ↔ content script ↔ runtime | `callHandler('wsi')` |
| popup UI | プラグイン管理画面 |
| (なし) | ワーカー、tabs、プラグインページ、メニュー、ネイティブブリッジ、ポリシー、更新チェック |

## 機能要件

### F-01: ブラウザ基盤

#### F-01-1: タブ
- 複数のサイトタブを保持し、切り替えられる。上限はホスト設定 (既定 5)
- 各タブは独立した `InAppWebView`。非表示タブは `IndexedStack` で保持する
- 起動時の初期 URL はホスト設定で指定できる。既定はホストのスタートページ (プラグイン一覧と URL 入力)

#### F-01-2: URL バーとナビゲーション
- URL 入力、戻る、進む、再読み込み、共有
- 現在のホストで有効なプラグイン数をバッジ表示する (WSI のバッジ相当)

#### F-01-3: ナビゲーション制御
- 外部リンク (プラグインが担当しないホスト) を「アプリ内で開く / 外部ブラウザで開く」のどちらにするかホスト設定で選べる
- `https` から `http` へのリダイレクトを検知し、`https` で読み直す (Android の cleartext 遮断と iOS ATS への対策。`http` を挟む 301 連鎖が遮断される事例を実機で確認済み)
- プラグインが `WSI.navigation.intercept` で遷移を横取りできる

#### F-01-4: JS ダイアログ
- `alert` / `confirm` / `prompt` を Flutter のダイアログとして表示する
- ワーカーが `WSI.tabs.onDialog` を登録したタブでは、ダイアログをワーカーに転送し、表示するか自動応答するかを決めさせる
- ただし Android は全 WebView が 1 つのレンダラを共有し、`alert()` が保留中はワーカーの JS も止まるため、ワーカーに問い合わせることができない。`onDialog(cb, {default})` の登録時に既定の応答 (accept / dismiss / show、既定 accept) をホストへ宣言し、Android ではその方針で即時応答してから `cb` に事後通知する。iOS では `cb` に先に問い合わせる (P4 で確定)

#### F-01-5: Cookie とセッション
- サイトタブ、プラグインページからの `WSI.fetch`、ワーカーのタブは同じ Cookie ストアを共有する
- Cookie の全消去をホスト設定から行える

#### F-01-6: ファイル選択とダウンロード
- `<input type="file">` を端末のファイル選択に接続する
- ダウンロードは端末の共有シートまたはダウンロードフォルダへ保存する

#### F-01-7: User-Agent
- ホスト設定で UA を上書きできる。既定は各 OS の標準ブラウザ相当

### F-02: プラグイン管理

#### F-02-1: インポート経路
以下のすべてに対応する。

| 経路 | 実現手段 |
|---|---|
| 端末内ファイル | `file_picker` で ZIP を選択 |
| 共有シート | 他アプリから ZIP を「WSI Browser で開く」。`receive_sharing_intent` |
| URL | `wsi://install?url=...` と管理画面の URL 入力。`app_links` |
| QR コード | URL を QR で読み取る。`mobile_scanner` |

#### F-02-2: 検証とプレビュー
- ZIP を `archive` で展開し、`plugin.json` を検証する (検証ルールは「プラグイン形式 v2」参照)
- プラグイン名、バージョン、説明、対象ドメイン、要求権限をプレビュー表示する
- 要求権限のうちユーザー確認が必要なもの (credentials、files、device など) を明示して同意を取る
- 同一 ID が存在する場合は上書き確認を表示し、`installedAt` と `plugin_data` を引き継ぐ

#### F-02-3: 一覧表示
- 名前、バージョン、対象ドメイン、説明、有効状態、権限、更新の有無を表示する
- 現在のタブのホストに一致するプラグインをハイライトする

#### F-02-4: 有効 / 無効
- プラグイン単位のトグルと、ホスト全体のキルスイッチを持つ
- 切り替えは次回のページ読み込みから反映する。ワーカーは即時に停止 / 起動する

#### F-02-5: 削除
- 確認ダイアログののち、プラグイン本体、`plugin_data`、`plugin_settings`、ボタン位置、資格情報、ワーカー状態、ポリシーキャッシュをすべて削除する

#### F-02-6: 更新チェック
- `plugin.json` の `updateUrl` に最新版情報 (JSON: `version`, `zipUrl`, `notes`) の URL を宣言できる
- ホストは起動時と 1 日 1 回に確認し、新しい `version` があれば一覧にバッジを出し、利用者の操作で更新する。自動適用はしない (ストア審査対策)
- 更新は上書きインポートと同じ経路を通り、`plugin_data` を保持する

#### F-02-7: エクスポート
- インストール済みプラグインを ZIP として書き出せる
- プラグインデータのバックアップと復元は、暗号化した JSON として書き出す

### F-03: プラグイン実行

#### F-03-1: ドメイン照合
- WSI と同じ `domains` 記法: 完全一致、`*.example.com`、`*`
- 追加で `paths` (任意) を受け付ける。glob 形式でパスを絞り込める。未指定なら全パス

#### F-03-2: 注入タイミング
- `document_start`: SDK コアと同じ UserScript として登録する (iOS `AT_DOCUMENT_START`、Android は同等)
- `document_end`: `AT_DOCUMENT_END` の UserScript
- `document_idle` (既定): `onLoadStop` 後に `evaluateJavascript`

#### F-03-3: 実行環境
- プラグインコードはメインワールドで実行する
- `WSI` は `window` に置かず、`new Function('WSI', code)` の引数として渡す。プラグイン間のグローバルは共有されない
- 実行時エラーはプラグイン単位で捕捉し、他のプラグインとホストに影響させない
- 同一ページ内で同じプラグインを二重実行しない

#### F-03-4: CSS 注入
- `styles[]` を結合して `injectCSSCode` で注入する
- ホストが描く UI (toast、dialog など v2 の UI) は Shadow DOM 内に描画し、サイトの CSS と衝突させない
- `WSI.addButton` と `WSI.addPanel` は Chrome 版との互換のため light DOM に描画する (既存プラグインが `.wsi-floating-button` を自前の CSS で装飾し、`panel.children[1]` を直接操作するため。P0 で確定)

#### F-03-5: SPA 遷移検知
- `onUpdateVisitedHistory` を `WSI.onPageLoad` に接続する。ホストはページに `wsi:urlchange` イベント (`window.dispatchEvent(new CustomEvent('wsi:urlchange'))`) を発火し、SDK はそれと `popstate` を監視する。MutationObserver 方式は補助として残す

#### F-03-6: メインフレーム限定
- iframe には注入しない (`forMainFrameOnly: true`)

### F-04: ブリッジとセキュリティ

#### F-04-1: 単一ハンドラとトークン
- ブリッジは `wsi` ハンドラ 1 本。すべての要求は `{token, op, payload}` の形を取る
- トークンは注入ごとにホストが発行し、pluginId と WebView に紐づく。ページ側が pluginId を自称することはできない
- 不正なトークンや未知の `op` は拒否し、ログに残す

#### F-04-2: 権限
- `plugin.json` の `permissions[]` で宣言した権限だけを許可する
- 権限一覧: `storage` (既定で許可)、`fetch`、`credentials`、`device`、`share`、`files`、`clipboard`、`wakeLock`、`pip`、`blockResources`、`tabs`、`pages`、`menu`、`navigation`、`policy`、`siteData`、`location`、`network`、`battery`、`biometrics`
- 未宣言の権限を要求した呼び出しは `{error: 'permission denied'}` を返す

#### F-04-3: 名前空間
- `plugin_data`、`plugin_settings`、`credentials`、ボタン位置、ポリシーキャッシュは pluginId で分離し、他プラグインから参照できない

#### F-04-4: ポリシー
- `plugin.json` の `policy.url` にポリシー値の取得先 (Workers API) を宣言できる
- ホストは起動時と `policy.ttlSeconds` ごとに取得し、`policy_cache` に保存する。取得に失敗したら最後のキャッシュ、キャッシュもなければ `policy.defaults` を返す
- プラグインは `WSI.policy.get(key)` で値を読み、その値に従って動作する。クライアント改変の完全な防止は目的としない (決定事項)。値の変更をサーバー側で即時反映できることを目的とする

#### F-04-5: ログ
- `WSI.log` の出力はホストのログ画面に集約し、プラグイン ID とタイムスタンプを付ける
- ログはローテーションし、共有シートで書き出せる

### F-05: ワーカー

#### F-05-1: 宣言と起動
- `plugin.json` の `background` に JS ファイルを指定すると、ホストはそれをワーカーとして `HeadlessInAppWebView` で起動する
- ワーカーには `WSI` の全 API (DOM 系を除く) が使える

#### F-05-2: ライフサイクル
- アプリ起動時、プラグイン有効化時に起動する
- クラッシュ時は指数バックオフで再起動する (上限 5 回)
- アプリが背面に移ったとき、ホストはワーカーへ `WSI.runtime.onSuspend` を通知し、ワーカーは状態を保存して一時停止する。復帰時に `onResume` を通知し、ワーカーは続きから再開する (決定事項)。iOS のバックグラウンド実行の延長は行わない
- 無効化、削除、ホスト全体 OFF で停止する

#### F-05-3: メッセージング
- `WSI.runtime.sendMessage(msg)` と `WSI.runtime.onMessage(cb)` で、ページ、プラグインページ、ワーカーの間を双方向に通信できる
- 配送はホストが行い、同じプラグイン内にしか届かない

#### F-05-4: 状態
- ワーカーの状態は `WSI.storage` に保存する。ホストは `worker_state` に最終起動時刻とエラーを記録する

### F-06: タブ操作 API

#### F-06-1: 操作
- `open(url, {hidden})`、`navigate(tabId, url)`、`run(tabId, code)`、`close(tabId)`、`list()`
- イベント: `onLoad(tabId, url)`、`onDialog(tabId, {type, message})`、`onClose(tabId)`
- `run` はコードの評価結果を返す

#### F-06-2: 表示と非表示
- `hidden: true` は `HeadlessInAppWebView`、`false` はユーザーに見える通常タブとして開く
- 「手動モードでタブを前面に出す / 自動モードで裏で回す」といった使い分けをプラグイン側で表現できる

#### F-06-3: 上限
- プラグインごとの同時タブ数はホスト設定で制限する (既定 3)

#### F-06-4: WebView の再生成
- iOS では既存 WebView への `loadRequest` が無視される既知の不具合がある。Android の `HeadlessInAppWebView` でも 2 回目の `loadUrl` が読み込みを開始しないことを確認したため (API 36 エミュレーター)、`navigate` は両 OS とも内部で WebView を作り直す。可視タブ (`hidden: false`) は使い回す。プラグインからはこの差を意識させない (P4 で確定)

### F-07: プラグインページ

#### F-07-1: スキーム
- `wsi://plugin/<pluginId>/<path>` でプラグイン同梱ファイルを配信する。`shouldInterceptRequest` でアプリ内ストレージから返す
- プラグイン ID の境界を越えるパス (`..`) は拒否する

#### F-07-2: 宣言と起動
- `plugin.json` の `pages` に名前とファイルを列挙する
- メニュー項目、`WSI.ui.openPage(name, params)`、ワーカーからの要求で開ける
- 表示形式は `fullscreen` と `sheet` から選べる

#### F-07-3: SDK
- プラグインページ内でも同じ SDK が使える。トークンはページ表示時に発行する
- プラグインページの HTML / JS はフレームワーク不使用の Vanilla JS を前提とする (WSI と同じ方針。前提事項)

#### F-07-4: fetch の Cookie
- `WSI.fetch(url, {credentials: 'site'})` で、サイトタブと同じ Cookie を付与して要求する。プラグインページの origin が対象サイトと異なる問題をこれで吸収する

### F-08: メニュー

#### F-08-1: 登録
- `WSI.menu.register(items)` で項目を登録する。種別は `page`、`action`、`toggle`、`separator`
- ワーカーまたはページから登録でき、ワーカーが登録したものはページ遷移で消えない

#### F-08-2: 表示
- ホストの AppBar のメニューボタンから、ホスト固有項目 (タブ、プラグイン管理、設定、ログ) の下にプラグインの項目を並べる
- 複数プラグインが登録した場合はプラグイン名で区切る

### F-09: ネイティブ機能ブリッジ

| API | 権限 | 内容 |
|---|---|---|
| `WSI.credentials.get/set/remove/list` | credentials | ID とパスワードを OS のセキュアストレージに保存する。プロファイル名で複数持てる |
| `WSI.device.id` / `info` | device | 端末 ID (Android は `android_id`、iOS は identifierForVendor)、OS、モデル |
| `WSI.device.key()` | device | プラグインごとの端末キー。HMAC-SHA256(端末の秘密値, pluginId) の 16 進 64 文字。秘密値は Android が `android_id`、iOS が Keychain (この端末のみ) に作る乱数。同じ端末の同じプラグインでは同じ値、プラグインが違えば無関係な値になる |
| `WSI.share({text, url, files})` | share | 共有シート |
| `WSI.files.save(name, data)` / `pick()` | files | ファイルの保存と選択 |
| `WSI.clipboard.write/read` | clipboard | クリップボード。ページでは `navigator.clipboard` も使える |
| `WSI.wakeLock.acquire/release` | wakeLock | 画面スリープ防止。参照カウントで管理する |
| `WSI.pip.enter/exit/isSupported` | pip | Android の Picture in Picture |
| `WSI.blockResources(rules)` | blockResources | 画像、動画、指定 URL の読み込みをブロックする。iOS は Content Rule List、Android は `shouldInterceptRequest` |
| `WSI.policy.get(key)` / `getAll()` / `refresh()` | policy | サーバー配信のポリシー値 |
| `WSI.ui.openUrl(url, {newTab})` | pages | プラグインページからサイトの URL をブラウザのタブで開き、そのページを閉じる |
| `WSI.settings.get/set/onChange` | (既定) | `settingsSchema` から生成される設定値 |
| `WSI.toast(msg)` / `WSI.dialog({title, message, buttons})` | (既定) | ネイティブのトーストとダイアログ |
| `WSI.navigation.intercept(cb)` | navigation | 遷移を横取りし、許可、拒否、別タブで開くを返す |
| `WSI.siteData.clear({cookies, storage})` | siteData | 自プラグインの `domains` に限って Cookie とサイトデータを消す (アカウント切替用)。同意が必要な権限 |
| `WSI.app.info()` | (既定) | WSI Browser のアプリ名、パッケージ名、バージョン、ビルド番号、OS |
| `WSI.locale.get()` | (既定) | 端末の言語一覧、ホスト UI の言語 (ja/en/ko/zh)、IANA タイムゾーン、UTC からの差 (分) |
| `WSI.location.permission()` / `request()` / `getCurrent({accuracy, timeout, maxAge})` | location | 現在地。アプリ使用中のみでバックグラウンド追跡はしない。未決定なら OS の許可ダイアログを出す。同意が必要な権限 |
| `WSI.network.status()` / `onChange(cb)` | network | 接続の有無と種類 (wifi、mobile、ethernet、vpn など)。インターネットに届くかまでは判定しない |
| `WSI.battery.status()` / `onChange(cb)` | battery | 残量 (%)、充電状態、省電力モード。`onChange` は充電状態が変わったときに届く |
| `WSI.biometrics.status()` / `authenticate({reason, biometricOnly})` | biometrics | Face ID、指紋、端末パスコードで本人確認し、成否だけを返す。ダイアログにはプラグイン名を付ける。ワーカーからは呼べない |

プッシュ通知のトークンは、Android では実質 FCM (Firebase) が必要でプロジェクト方針と両立しないため提供しない (2026-09-13 決定)。

### F-10: 設定と i18n

- ホスト設定: 初期 URL、タブ上限、外部リンクの扱い、UA、ログ保持量、開発者モード、更新チェックの有無
- プラグイン設定: `plugin.json` の `settingsSchema` (項目名、型、既定値、説明) からホストが設定画面を自動生成する。複雑な設定はプラグインページで実装する
- UI 文言は `flutter_localizations` と arb で管理し、ja / en / ko / zh_CN を用意する (WSI と同じ 4 言語)。既定は ja

### F-11: 開発者支援

- 開発者モードで URL からのライブリロード (`wsi://dev?url=https://<PC>/plugin.zip`) を有効にし、指定間隔で再取得する
- ログ画面で `WSI.log`、ブリッジエラー、注入結果 (位置と可視性の自己診断) を確認できる
- iOS は Safari Web インスペクタ、Android は `chrome://inspect` を有効化する設定を持つ

### F-12: サイト固有プラグインの要件

サイト固有プラグインの要件は各プラグインのリポジトリ側で定義する。ホストが保証するのは、以下の SDK と仕組みが揃っていることである。

| プラグインが必要とする仕組み | 対応する要件 |
|---|---|
| ページへのボタン、パネル、DOM 操作 | F-03、SDK 既存 API |
| 設定画面、一覧画面などの独自 UI | F-07 プラグインページ、F-08 メニュー |
| ログイン情報の保存 | F-09 credentials |
| ページを跨いで動き続ける自動処理 | F-05 ワーカー、F-06 tabs |
| サーバーから配信される制限値 | F-04-4 ポリシー |
| 他アプリからのデータ取り込み | F-09 files + プラグイン側の変換処理 |
| プラグインの更新 | F-02-6 |

### F-13: バックエンド (apps/api)

Cloudflare Workers + D1。ホストとプラグインから `WSI.fetch` で呼ぶ。特定プラグイン専用にせず、プラグイン ID をキーにした汎用 API とする。

| エンドポイント | 内容 |
|---|---|
| `GET /v1/plugins/:id/policy` | ポリシー値 (JSON)。D1 の `plugin_policies` から返す |
| `GET /v1/plugins/:id/latest` | 最新バージョン、ZIP の URL、更新ノート。`updateUrl` の参照先 |
| `POST /v1/feedback` | プラグイン ID、端末情報、本文。D1 の `feedback` へ保存 |
| `GET /v1/plugins/:id/releases/:version.zip` | R2 (非公開) の ZIP を Worker が返す |
| (静的) | Worker の静的アセットとして配布ページ (QR 付き) を出す |

- 認証は当面なし。書き込みは `feedback` のみで、レート制限を Workers で行う
- D1 テーブル: `plugin_policies (plugin_id, key, value, updated_at)`、`plugin_releases (plugin_id, version, zip_url, notes, released_at)`、`feedback (id, plugin_id, device, body, created_at)`
- 将来のプラン体系は別書で設計し、このスキーマに追加する

## プラグイン形式 v2

### ディレクトリ構成

```
my-plugin/
├── plugin.json          # 必須
├── main.js              # 必須 (ページ注入)
├── worker.js            # 任意 (ワーカー)
├── style.css            # 任意
├── pages/               # 任意 (プラグインページ)
│   ├── settings.html
│   └── settings.js
└── assets/              # 任意 (テンプレート、画像)
```

### plugin.json

```json
{
  "formatVersion": 2,
  "id": "example-site",
  "name": "Example Site Plus",
  "version": "1.0.0",
  "description": "example.com 向け機能拡張",
  "author": "Serendipy",
  "domains": ["example.com", "*.example.com"],
  "paths": ["/manage/**", "/blog/**"],
  "scripts": { "main": "main.js", "runAt": "document_idle" },
  "styles": ["style.css"],
  "background": "worker.js",
  "pages": {
    "settings": { "file": "pages/settings.html", "display": "fullscreen" },
    "queue":    { "file": "pages/queue.html",    "display": "sheet" }
  },
  "menu": [
    { "id": "settings", "label": "設定", "type": "page", "page": "settings" },
    { "id": "queue",    "label": "キュー", "type": "page", "page": "queue" }
  ],
  "permissions": ["fetch", "credentials", "tabs", "pages", "menu", "share", "wakeLock", "policy"],
  "settingsSchema": [
    { "key": "lineBreakCount", "type": "number", "label": "改行数", "default": 2 }
  ],
  "policy": {
    "url": "https://api.example.workers.dev/v1/plugins/example-site/policy",
    "ttlSeconds": 3600,
    "defaults": { "minActionIntervalMs": 3000 }
  },
  "updateUrl": "https://api.example.workers.dev/v1/plugins/example-site/latest",
  "config": { "targetPath": "/manage/" }
}
```

### 検証ルール

| フィールド | 型 | 必須 | ルール |
|---|---|---|---|
| formatVersion | number | - | 1 または 2。省略時 1 (Chrome 版 WSI 互換) |
| id | string | ○ | `^[a-zA-Z0-9-]+$` |
| name | string | ○ | |
| version | string | ○ | セマンティックバージョニング |
| description, author | string | - | |
| domains | string[] | ○ | 1 つ以上。WSI と同じ記法 |
| paths | string[] | - | glob。省略時は全パス |
| scripts.main | string | ○ | ZIP 内に存在すること |
| scripts.runAt | string | - | document_start / document_end / document_idle |
| styles | string[] | - | ZIP 内に存在すること |
| background | string | - | ZIP 内に存在すること。`tabs` を使うには `permissions` に宣言が必要 |
| pages | object | - | 各 `file` が ZIP 内に存在し、`display` は fullscreen / sheet |
| menu | array | - | `type` は page / action / toggle / separator。`page` は `pages` に存在すること |
| permissions | string[] | - | F-04-2 の一覧に含まれること |
| settingsSchema | array | - | `key`, `type` (string / number / boolean / select), `default` |
| policy | object | - | `url` は https。`ttlSeconds` は 60 以上。`defaults` は object |
| updateUrl | string | - | https |
| config | object | - | |

### 後方互換

- `formatVersion` 未指定または 1 の ZIP は Chrome 版 WSI と同じ扱いで動作する
- Chrome 版 WSI は v2 の追加フィールドを無視するため、v2 プラグインの `main.js` 部分は Chrome でも動作する。ただし v2 専用 API を呼ぶと `WSI.xxx is undefined` になるため、`WSI.permissions.has('tabs')` で分岐する

| addButton, addPanel, onPageLoad | ○ | × | × |
| storage, fetch, getConfig, log, settings, policy, toast, dialog, permissions | ○ | ○ | ○ |
| runtime.sendMessage / onMessage / onSuspend / onResume | ○ | ○ | ○ |
| ui.openPage / closePage | ○ | ○ | ○ |
| menu.register | ○ (ページ寿命) | ○ | ○ (常駐) |
| tabs.* | × | × | ○ |
| credentials, device, share, files, clipboard, wakeLock, pip, blockResources, siteData.clear | ○ | ○ | ○ |
| app, locale, location, network, battery, biometrics.status | ○ | ○ | ○ |
| biometrics.authenticate | ○ | ○ | × |
| navigation.intercept | × | × | ○ |

### 既存 API (Chrome 版と同じ)

- `WSI.addButton({text, icon, position, onClick})` : Pointer Events でドラッグ可能。タップ領域 44pt 以上。safe area を考慮する
- `WSI.addPanel({title, width, position, content, onOpen, onClose})` : 画面幅 600px 未満では全幅のボトムシートとして表示する
- `WSI.storage.get/set/remove/getAll`
- `WSI.fetch(url, options)` : 既存に加え `credentials: 'site' | 'omit'`、`responseType: 'text' | 'json' | 'arraybuffer'`、`timeoutMs` を受け付ける。既定メソッドは HEAD (互換維持)
- `WSI.onPageLoad(cb)`、`WSI.getConfig()`、`WSI.log(msg)`

### 新規 API

```javascript
// UI
WSI.toast(message, {duration});
await WSI.dialog({title, message, buttons: ['OK', 'キャンセル']});   // 押されたボタンの index
await WSI.ui.openPage(name, params);
WSI.ui.closePage();

// メニュー
WSI.menu.register([{id, label, icon, type, page, checked, onSelect, onChange}]);
WSI.menu.update(id, {label, checked});

// メッセージングとライフサイクル
WSI.runtime.sendMessage(message);          // 同一プラグイン内の全コンテキストへ
WSI.runtime.onMessage((message, sender) => reply);
WSI.runtime.onSuspend(async () => {});     // 背面移行 (ワーカー)
WSI.runtime.onResume(async () => {});      // 復帰 (ワーカー)

// タブ (ワーカー限定)
const tabId = await WSI.tabs.open(url, {hidden: true});
await WSI.tabs.navigate(tabId, url);
const result = await WSI.tabs.run(tabId, code);
await WSI.tabs.close(tabId);
WSI.tabs.onLoad((tabId, url) => {});
WSI.tabs.onDialog((tabId, {type, message}) => ({action: 'accept' | 'dismiss' | 'show'}));

// ポリシー
await WSI.policy.get('minActionIntervalMs');
await WSI.policy.getAll();
await WSI.policy.refresh();

// ネイティブ
await WSI.credentials.set(profile, {id, password});
await WSI.credentials.get(profile);
await WSI.device.id();
await WSI.share({text, url});
await WSI.files.save(name, data, {mime});
await WSI.files.pick({accept});
await WSI.clipboard.write(text);
await WSI.wakeLock.acquire(); await WSI.wakeLock.release();
await WSI.pip.enter(); await WSI.pip.isSupported();
await WSI.blockResources({images: true, media: true, urls: []});
await WSI.settings.get(key); await WSI.settings.set(key, value); WSI.settings.onChange(cb);
WSI.permissions.has('tabs');
WSI.navigation.intercept((url, tabId) => 'allow' | 'deny' | 'external');
```

## 非機能要件

### パフォーマンス
- SDK コアの注入がページ表示を体感で遅らせないこと (UserScript は 30KB 以下)
- プラグイン非対象ドメインでは drift の 1 クエリ以外の処理を行わない
- 同時に保持する WebView はサイトタブ、プラグインページ、ワーカーを合わせてホスト設定の上限内 (既定 8)

### セキュリティ
- ブリッジのトークン検査、権限検査、名前空間分離を必須とする
- `wsi://` スキームはプラグイン自身のファイルしか返さない
- 資格情報はセキュアストレージのみ。ログに出さない
- Firebase 関連パッケージと既存アプリのバックエンド識別子をコードに含めない。CI で検査し、検出したら失敗させる

### ストア審査
- プラグインは利用者が自分の意思でインポートする。更新も利用者の操作で行い、ホストが自動適用することはない
- Apple ガイドライン 2.5.2 (WebKit 内で実行される JavaScript は許容) の範囲で設計する
- 審査ノートに「利用者が自作または入手したスクリプトを自分のブラウザで実行する開発者向けツール」であることを明記する

### 互換性
- iOS 15 以上、Android 8 (API 26) 以上 (前提事項)
- Flutter 3.41 系、flutter_inappwebview 6 系
- Chrome 版 WSI の v1 プラグイン (同梱サンプル 7 個) がそのまま動くこと

### 保守性
- SDK コアは `packages/wsi_sdk` に置き、単一のソースから Chrome 版と Flutter 版のアダプタを生成する。Chrome 版 WSI もこの SDK に載せ替える
- SDK の契約テスト (サンプルプラグインを両ホストで実行) を CI で回す
- ホストはプラグインの種類を知らない。サイト固有のロジックはすべてプラグイン側に閉じ込め、新しいサイトへの対応はプラグインの追加だけで完結する
- プラグインは 1 ディレクトリ 1 プラグインとし、機能は `src/features/` に 1 機能 1 ファイルで置く。雛形からの生成、検証、ZIP 化、PC からの配信、Cloudflare への公開を CLI で行う
- ホストへの変更が必要なのは新しいネイティブ機能を足すときだけで、その場合も `bridge_ops/` に 1 ファイル追加し権限一覧に追記する形に限定する (詳細は [実装プラン.md](実装プラン.md) 第 2 章)

## スコープ外

- Chromium や Gecko のフォーク
- ネットワーク層 (VPN / プロキシ) での注入
- 他ブラウザ (Safari / Chrome) への注入
- プラグインのマーケットプレイスと自動配信
- 課金とプラン体系 (別書で設計)
- Flutter Web、デスクトップ
- サイト固有プラグインの要件 (各プラグインのリポジトリで定義)
